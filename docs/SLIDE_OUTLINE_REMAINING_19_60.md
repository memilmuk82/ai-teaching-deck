# 남은 슬라이드 상세 개요: 19~60

## 전체 연수 목표

- 연수 제목: **매번 설명하지 않는 AI 수업자료 생성기 만들기**
- 부제: **AI와 함께 프롬프트를 설계하고, 반복 사용할 수 있는 구조로 다듬기**
- 핵심 목표: 생성형 AI의 도움으로 만든 프롬프트를 다른 단원과 자료에도 반복 적용할 수 있도록 교육과정 지식 파일, 고정값, 변수, 제작 제한, 출력 형식, 검토 기준을 갖춘 **프롬프트 하네스**로 다듬는다.
- 최종 산출물:
  1. 자신의 교과 교육과정 Markdown이 연결된 클래식 Gemini Gem
  2. 자신의 수업 원칙이 반영된 Gem 지시사항
  3. 첫 번째 단원 시험 결과
  4. 다른 단원 전이 시험 결과
  5. 시험 결과를 보고 수정한 생성기 규칙
- 핵심 메시지: 이번 연수의 산출물은 활동지 한 장이 아니라 반복해서 사용할 수 있는 수업자료 생성기다.

## 슬라이드 1~18과의 연결

슬라이드 18은 이미지에서 표현 방식을 고정했던 경험을 수업자료의 구조와 교수 원칙으로 옮기며 끝난다. 이어지는 슬라이드 19는 슬라이드 18의 첫 번째 다음 단계인 **교과별 교육과정 Markdown 연결**을 바로 실행한다. 이미지 프롬프트에서 사용한 `관찰 → 특징 추출 → 구조화 → 다른 입력에 적용 → 검토 → 규칙 수정`의 흐름은 다음과 같이 확장된다.

`교육과정 탐색 → 수업 원칙 추출 → Gem 지시사항 구조화 → 첫 단원 생성 → 전이 시험 → 생성기 규칙 개선`

## 통합 교육과정 자료 활용 원칙

1. 참가자는 ZIP 전체가 아니라 압축을 푼 뒤 `교과/` 아래의 **자신의 교과 Markdown 파일 하나만** Knowledge에 연결한다.
2. `README.md`, `manifest.json`, `MERGE_REPORT.md`는 강사와 Codex가 통합 방식과 검증 상태를 확인하는 자료이며, 일반 참가자가 Gem에 넣는 지식 파일이 아니다.
3. 교과별 Markdown은 PDF 전체보다 검색 범위와 교과 경계를 명확하게 유지하는 데 유리하다.
4. 교육과정 파일은 수업자료의 범위와 근거를 제공하지만 교사의 수업 방법, 학생 상황, 활동 선호를 대신 결정하지 않는다.
5. 한 번에 여러 교과 파일을 연결하면 관련성이 낮은 성취기준이 섞일 수 있으므로 기본 실습에서는 한 교과만 사용한다.
6. AI는 파일에 없는 성취기준을 만들거나 추측하지 않으며, 교사는 코드와 원문을 파일에서 직접 확인한다.
7. 생활 외국어 8개 파일은 `[원문 확인 필요]` 표시가 많은 OCR 주의 자료다. 표시를 지우거나 임의로 교정하지 않고, 공식 PDF 대조가 필요한 조건부 자료로만 다룬다.
8. 화면에 표시되는 모든 문구와 프롬프트는 향후 콘텐츠 객체의 일반 문자열과 선택·복사 가능한 DOM 텍스트로 구현한다.

이 문서에서 `README.md`, `manifest.json`, `MERGE_REPORT.md`, `교과/정보.md`처럼 줄여 쓴 근거 경로는 모두 압축 해제 최상위 폴더인 `tmp/curriculum-work/2022개정_중학교_교육과정_통합_Markdown/`을 기준으로 한 실제 상대 경로다.

- **공식 코드가 모두 포함된 파일:** 24개
- **README 주요 내용:** 연수용 계층형 Markdown을 본문으로 채택하고 공식 원문 변환본은 성취기준 코드와 주요 구조의 대조 기준으로 사용했다. 두 본문을 중복 수록하지 않았으며 참가자는 ZIP 전체가 아니라 자신의 교과 파일 하나만 Gem Knowledge에 연결한다.
- **manifest 주요 내용:** 24개 파일의 출처, 병합 방식, 상태, 성취기준 코드 대조 수, 확인 표시 수, 해시를 기록한다. 일반·선택 교과 16개는 `검증 완료`, 생활 외국어 8개는 `OCR 주의`다. 생활 스페인어·중국어·아랍어는 공식 코드 전체를 포함하지만 연수용 코드에 추가 OCR 의심 코드가 있어 완전 일치가 아니다.
- **MERGE_REPORT 주요 내용:** 일반·선택 교과 16개는 확인 표시 0개이며 코드가 완전 일치한다. 생활 외국어는 확인 표시가 과목별 228~356개이고 공식 PDF 확인을 병행하는 조건부 사용을 권장한다. 시범 교과로 정보, 국어, 수학, 과학, 사회, 역사를 권장한다.
- **우선 분석한 6개 교과:** 정보 25개, 국어 51개, 수학 60개, 과학 87개, 사회 74개, 역사 40개 성취기준. 각 파일에서 통합본 정보, 문서 정보, 교육과정 설계의 개요, 성격과 목표, 내용 체계, 핵심 아이디어, 지식⋅이해, 과정⋅기능, 가치⋅태도, 성취기준 원문·해설·적용 시 고려 사항·원문 쪽수, 교수⋅학습, 평가, 원문 확인 필요 사항을 확인했다.
- **시범 사례로 선택한 교과와 이유:**
  - 정보: 오류 찾기와 개인정보 보호라는 서로 다른 활동 구조로 전이 시험을 명확하게 보여 줄 수 있다.
  - 국어: 주장·근거와 작품 해석 모두 `근거`를 사용하지만 출력 구조가 달라, 유지할 원칙과 바뀔 활동을 비교하기 좋다.
  - 과학: 개념 분류와 실험 결과 해석으로 사고 행동을 전환할 수 있다.
  - 사회: 일상 사례 판단과 자원 통계·자료 해석으로 자료 유형의 전이를 보여 줄 수 있다.
  - 수학과 역사는 근거 범위를 확인했으며, 필요 시 그래프 해석·사료 분석의 추가 사례로 사용할 수 있다.
- **분석상의 한계와 확인 사항:** 통합 ZIP에는 메타데이터가 가리키는 공식 원문 Markdown과 원본 PDF 자체가 들어 있지 않아 이번 분석은 통합본 내용, 기록된 코드 대조 결과, 파일 구조와 manifest 해시를 확인한 것이다. 수학 통합본의 일부 성취기준 문장 끝에 다음 소제목이 붙은 변환 흔적이 확인되었다. 예를 들어 `[9수04-04]` 끝의 `경우의 수와 확률`은 공식 PDF 대조 전 화면 예시로 사용하지 않는다. `검증 완료` 상태를 모든 문장부호와 변환 결과의 무오류 보증으로 해석하지 말고, 실제 활용 전 코드·원문과 공식 PDF를 교사가 최종 확인한다.

## C. 웹앱 구현 시 필요한 신규 자산

| 자산 | 준비 방법 | 주의 사항 |
|---|---|---|
| 실제 Gemini Gem 설정 화면 캡처 | 후속 구현 직전에 강사가 최신 실제 화면을 직접 캡처 | 계정명, 이메일, 대화 내용 등 개인정보 제거. 계정별 기능을 일반화하지 않음 |
| Knowledge 파일 선택 화면 | 자신의 교과 Markdown 하나를 선택하는 실제 과정을 직접 캡처 | ZIP 전체나 여러 교과 파일이 선택된 화면을 정답 예시로 사용하지 않음 |
| 지시사항 작성 화면 | 9개 영역 지시사항을 붙여 넣는 실제 화면 캡처 | 최신 UI 확인 전 가짜 UI를 실제 화면처럼 만들지 않음 |
| 첫 단원 시험 결과 | 정보 오류 찾기 또는 강사가 선택한 교과의 실제 시험 A 결과 | 입력, 원본 결과, 검토표를 함께 보존하고 개인정보 제거 |
| 전이 시험 결과 | 같은 Gem에서 다른 단원으로 실행한 실제 시험 B 결과 | A·B의 고정값과 변경 변수를 비교할 수 있어야 함 |
| 전후 규칙 비교 화면 | 변경 전 규칙, 발견 증거, 변경 후 한 줄을 실제 기록으로 제작 | 결과 일부만 고친 사례와 혼동하지 않게 라벨 표시 |
| 체크리스트 아이콘 | 기존 Material 계열 시각 언어와 맞는 라이선스 확인 아이콘 또는 CSS/DOM 도형 | 색만으로 상태를 구분하지 않음 |
| 파일 선택 아이콘 | 기존 디자인과 맞는 교체 가능한 SVG | SVG 안에 설명 문자를 넣지 않음 |
| Google 또는 Android 계열 캐릭터 | 저장소의 기존 `teacher`, `ai-helper`, `reviewer`, `student` 자산 재사용 | 공식 자산으로 교체할 때 라이선스·브랜드 지침 확인. 말풍선 문자는 DOM 텍스트로 유지 |

실제 Gemini UI 관련 자산은 모두 **후속 구현 시 최신 화면을 직접 캡처해야 하는 항목**이다. 캡처가 준비되지 않으면 파일 선택, 지시사항, 시험 결과를 선택·복사 가능한 DOM 텍스트 카드와 중립 placeholder로 구현한다.
